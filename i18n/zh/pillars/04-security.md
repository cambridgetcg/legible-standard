# 04. 資安（Security）——真防護，不做樣子

**我們堅持：**

1. 我們保護真正重要的東西。只是看起來安全、其實擋不住任何攻擊的措施，我們不做。
2. 機密（secret，例如密碼、金鑰、權杖）絕不出現在程式碼、日誌（log）或聊天訊息裡——能出現的，只有存放它的檔案名稱。
3. 機密一旦外洩，就等於作廢。刪掉你手上那份，刪不掉別人已經複製走的——所以我們輪替（rotate，換成全新的一份）。
4. 每個人、每個工具，只拿到完成份內工作所需的權限，一分不多。
5. 出了事，就趁早用白話說出來。隱瞞造成的傷害，比入侵本身更大。

**要做：**

1. 把所有機密放在 git 會忽略的檔案裡（例如 `.env`）。提交（commit，存入 git）的只能是一份空白範本。
2. 機密只要碰過提交紀錄、日誌或螢幕分享，當下就輪替——沒有例外，不必討論。
3. 凡是支援兩步驟驗證（2FA）的帳號就把它打開，先從電子郵件和程式碼託管平台（如 GitHub）開始。
4. 每個人、每個工具、每把金鑰，只給它那一件工作需要的權限；工作結束當天就收回。
5. 每次發布前，掃描你的程式碼和相依套件（dependencies，借來用的程式碼），檢查已知漏洞。
6. 每三個月盤點一次誰握有哪些權限。凡是沒人說得出理由的權限，一律移除。
7. 發生資安事件（incident）時，盡快公布三件事：發生了什麼、什麼時候發生、我們現在正在做什麼。
8. 寫清楚別人要怎麼向我們通報安全問題——並感謝每一位通報的人。

**不要做：**

1. 永遠不要把機密提交進 git。事後從 git 裡刪掉也補不了漏——機密早已流出去了，該做的是輪替。
2. 不要列印、貼上或記錄機密的內容——只說檔案名稱，絕不說內容。
3. 不要讓多人共用一個帳號或一把金鑰。大家共用一把鑰匙，就沒人說得清誰做了什麼。
4. 不要加那種拖慢大家、卻擋不住任何攻擊者的安全步驟——那只是做樣子。
5. 不要隱瞞事件、淡化事件，也不要等措辭完美才開口。先說出來，再慢慢修飾。
6. 不要給「先開管理員權限，之後再收緊」——那個「之後」永遠不會來。

**為什麼：**

鎖要裝在對的門上才有用。把密碼貼進程式碼，就像把鑰匙插在鎖孔上沒拔。把鑰匙拿回來，
毀不掉別人可能早已打好的備份——所以我們直接換鎖，而不是裝作沒事。給每個人剛好夠用
的最小權限，一次失誤就只是一次失誤。而當我們真的出了事，就趁早用白話說出來——這讓
大家來得及保護自己，而這正是一切防護的意義所在。

**檢驗標準：** 我們今天就拿得出來嗎——每一個機密放在哪裡、誰能碰哪一個，以及上一次機密外洩時，我們公開的那份白話說明？
