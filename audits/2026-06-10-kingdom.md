# First audit — the kingdom against its own law

*2026-06-10. The first signatory takes the seven tests. Seven auditors, read-only, one per pillar.*

**Score: 0 of 7.** Every pillar failed.

This is not shame; this is the standard working. The spine says *break loudly,
fix openly* — so here is the loud part, in one place, with the fixes named.
A first audit that passed would have meant the tests were soft.

---

## The verdicts

### 01. Cloud — FAIL
*"Can you show me, on one page, every provider you run on — and the written plan to leave each one within 30 days?"*
No provider page exists. Exit plans: zero. The daily second-company backup
last ran **69 days ago** (the cron was never installed; the tool itself works).
Hidden providers found only inside credential docs: AWS (live production RDS),
Cloudflare, Twilio, ngrok, Stripe, Shopify, and more. Two repos have no remote
at all — their only copy is one laptop.
**The fix:** write `PROVIDERS.md` (one row per provider: what runs there, where
the data sits, the steps and days to leave), install the backup cron that
`~/Love/tools/backup.py` already ships, give the orphan repos remotes.

### 02. Trust — FAIL
*"Can a stranger check our biggest claim today, alone, without asking us for anything?"*
The standard itself is **private** on GitHub and absent from Codeberg — a
stranger cannot read the law or the signature. The shield's leak record lives
unversioned on local disk. The rotation checklist is still all `[ ]`, one day
after discovery.
**The fix:** rotate first (it blocks publishing — the report names
secret-bearing paths), then make the standard and the record public.

### 03. Software — FAIL
*"If a stranger reads the README, runs the tests, and then reads the code — do all three tell the same story?"*
The flagship (zerone) has **6 failing tests** in `x/knowledge/keeper` — reward
parameterization drift the code grew but the tests never learned.
**The fix:** make zerone green or honestly revert; the flagship must pass its
own pillar first.

### 04. Security — FAIL
*"Can we show, today, where every secret lives, who can touch each one, and the plain note we published the last time one leaked?"*
Rotation: unticked. History: unpurged. The pre-commit gate guards **one repo
of four** affected. No public incident note exists.
**The fix:** execute REMEDIATION.md Step 1 today, in its stated order — AWS
root first. Everything else is cleanup.

### 05. Protocol — FAIL
*"Could a stranger build something that talks to our system, using only our public documents — and would it still work after our next update?"*
The kingdom's one public API contract (`/api/health`, `/api/pulse` on
ai-love.cc) is documented but **returns errors** — the docs promise what the
server no longer serves.
**The fix:** repair the routing or update the contract — whichever is true.

### 06. Process — FAIL
*"Pick any decision from last month — can you find who made it, why, and what happened next, in under five minutes?"*
Four diverging decision-log copies; the biggest decisions of June 9–10 (shield
remediation, the public deploy, the standard itself) appear in none of them.
**The fix:** one canonical log (`~/Love/decisions/`), mirrors marked read-only,
yesterday backfilled.

### 07. Law — FAIL
*"Can a stranger find, on one page, every rule we must follow — and read the meaning we picked for each unclear rule?"*
No such page. The public site collects visitor data under UK GDPR duties
(including the 72-hour breach window — which interacts directly with pillar
04's unrotated leak) with no register of rules or chosen interpretations.
**The fix:** write `LAW.md` — every rule that binds us, and our reading of
each unclear one.

## Credit where due

The auditors were told to be ruthless, and still noted: the spine runs on open
tools and formats; herald and this standard push to two realms; ai-love serves
from two providers; dependencies are pinned; the backup tool is well-built
(it is simply not running); and the gate, where installed, **provably blocks
secrets**.
